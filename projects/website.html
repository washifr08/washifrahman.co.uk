What it is

This website is my portfolio, but it is also a project in its own right. Rather than using a website builder, I decided to put it online the way a company would, which meant renting a server in the cloud, pointing a domain at it, securing it and working out how to update it. Whilst this took far longer than dragging and dropping a template, it forced me to understand how each piece works and how they all connect, which is exactly what I want to learn as someone interested in cloud architecture.

How a visit reaches the page

When someone types washifrahman.co.uk into their browser, the request goes to Cloudflare first, which handles it at its nearest data centre and then passes it on to my server in Oracle Cloud's London region. Before it reaches the server, the request has to get through two firewalls, one in Oracle's network and one on the server itself, and only then does Nginx, the web server software, send back the page.

How I built it

Below I have listed the main stages in the order I worked through them.

  1. Registering the domain

    I bought washifrahman.co.uk through names.co.uk, and later moved its DNS, which is essentially the internet's address book, over to Cloudflare.

  2. Creating the server

    I created an Always Free virtual machine on Oracle Cloud Infrastructure in London, running Ubuntu Linux, along with the virtual cloud network, public subnet and internet gateway it needs to reach the internet. I manage it over SSH with a key pair rather than a password.

  3. Opening the right ports

    I opened only the ports the site needs, in both Oracle's security list and the server's own iptables firewall.

  4. Serving the site

    Nginx serves the site's files, and I configured it to refuse requests for the hidden Git folder, so the project's history is never exposed.

  5. Adding HTTPS

    The site uses free Let's Encrypt certificates, which only last 90 days, so Certbot renews them automatically. It proves I own the domain by adding a temporary DNS record through a Cloudflare API token that can only edit this one domain.

  6. Putting Cloudflare in front

    Visitors connect to Cloudflare rather than to my server directly, and the connection is encrypted on both legs, from the visitor to Cloudflare and from Cloudflare to my server.

  7. Automating deployments

    The site's code lives on GitHub, and a script on the server checks for changes every minute, so anything I push goes live within about a minute without me needing to log in.

  8. Setting up email

    Emails sent to my domain are forwarded to my inbox using Cloudflare Email Routing.

Keeping it secure

Once everything was working, I locked the server down so that it only accepts web traffic from Cloudflare's published IP ranges, which means nobody can get around Cloudflare by visiting the server's address directly, and I limited SSH access to my own IP address.

I also chose to have the server pull updates from GitHub, rather than letting GitHub log in and push them, because it meant I did not need to open any extra ports. The cost of this decision is a wait of up to a minute before changes appear, which I consider a fair trade for a server that accepts fewer connections.

Problems I ran into

The wrong system image

My first attempt at creating the server failed because I had chosen an Ubuntu image built for ARM processors, whilst the free server I had picked runs on an AMD processor, so I had to switch to the matching x86 image.

Firewall rules in the wrong order

Even after opening the web ports, the site still would not load, and I eventually realised that iptables reads its rules from top to bottom, and my new rules had been added below the one that rejects everything else.

Old DNS records

After locking the server down, the site stopped loading on my own laptop whilst working everywhere else. My broadband provider was still handing out the server's old address from before the move to Cloudflare, which my new firewall rules were correctly blocking, and it sorted itself out once the provider's cached records expired.
